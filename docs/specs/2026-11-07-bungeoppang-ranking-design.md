# 붕어빵 랭킹전 기획서

> 상태: 확정 · 2026-11-08 · **독립 상시 앱** `apps/bbang`, 주소 `bbang.arosys.kr` · 1~5단계 구현(첫 출시 범위)
> (2026-11-08 플레이 피드백으로 5.1·5.2 규칙 변경: 반죽 못 뺌 · 거치대 · 쓰레기통 · 식음,
> 15장 가게 경제 추가: 매출 → 포인트 → 상점 업그레이드).
>
> 두 가지를 정했다. (1) "붕어빵 만들기" 한 판의 게임 규칙, (2) "랭킹전"을 **서버 없이** 어떻게
> 만들지. 송이랜드는 지금까지 **서버 없음 · 브라우저 저장만** 원칙을 지켜 왔고(로또쇼·견생극장),
> 이 기획도 그 원칙을 1순위로 둔다.
>
> **"이벤트 게임"의 뜻**: 겨울 길거리라는 시즌 테마와 **매일 바뀌는 "오늘의 장사"(일일 챌린지)**가
> 이벤트 같은 느낌을 준다는 뜻이고, 기간 한정이 아니라 **늘 열려 있는 독립 앱**이다.

## 1. 한 줄 소개

겨울 길거리 붕어빵 가게 사장이 되어, 손님 주문대로 붕어빵을 **제 타이밍에 구워 내는** 1~2분짜리
타이밍 게임. 매일 바뀌는 "오늘의 장사"로 전 세계가 같은 판을 플레이하고 점수를 겨룬다.

## 2. 확정된 결정 (2026-11-08)

| 항목 | 결정 |
| ---- | ---- |
| 앱 성격 | **독립 상시 앱.** 로또쇼·견생극장처럼 늘 열려 있다. "이벤트"는 겨울 시즌 테마 + 일일 챌린지 느낌이다. |
| 장르 | **타이밍·주문 처리 게임.** 반죽 → 소 넣기 → 굽기 → 뒤집기 타이밍 → 완성. |
| 한 판 길이·종료 | **시간제, 90초 한 판.** 끝이 명확하고 점수 비교가 쉬워 랭킹에 맞다(5.5). |
| 랭킹 방식 | **1단계는 완전 무서버.** 시드 기반 일일 챌린지 + 로컬 최고기록·고스트 + 공유 카드. 온라인 전역 순위표는 **나중 선택지**(6.2), 처음 목표로 두지 않는다. |
| 소 종류 | **팥·슈크림 2종으로 시작**, 장사 후반에 고구마(또는 피자) 1종이 더해진다(5.3). |
| 과금·상품 | **없음.** 실제 돈·구매는 없다. 게임 안에는 점수와, 플레이로만 버는 **가게 포인트**(15장)가 있다. 확률 보상이 없어 사행성과 거리가 멀다. |
| 저장·공유 | **이 브라우저에만 저장, 결과는 공유 카드 이미지.** 서버는 두지 않는다. |
| 비주얼 | **글·도형 중심 + 직접 만든 붕어빵 SVG.** 외부 그림·폰트·음원은 라이선스 확인 전엔 안 쓴다. |
| 사운드 | **첫 출시에는 넣지 않는다**(견생극장 규칙과 같게). 넣는다면 Web Audio 효과음부터, 라이선스 기록. |
| 톤 | **밝고 아기자기.** 붕세권·가슴속 3천원 같은 겨울 길거리 밈을 가볍게 얹는다. |
| 이름·주소 | **붕어빵 랭킹전**, 앱 폴더 `apps/bbang`, 주소 `bbang.arosys.kr`, 포트 5177/4177(10장). 표시 이름은 구현 때 쉽게 바꿀 수 있다. |

## 3. 성공 기준

- 처음 온 사람이 설명 없이 **10초 안에 첫 붕어빵을 굽기** 시작한다.
- 한 판이 1~2분 안에 끝나고, 끝나면 "오늘 기록 깨기" 또는 "내일 또"를 누르고 싶어진다.
- **같은 날이면 누구나 같은 판**을 플레이해, 친구와 점수를 바로 비교할 수 있다(서버 없이).
- 뒤집기 타이밍이 **손맛**이 있다. Perfect 판정이 "딱!" 하고 꽂히는 맛이 반복 플레이를 만든다.
- 결과 카드를 이미지로 저장해 SNS에 올릴 수 있다.

## 4. 핵심 흐름

```text
시작(오늘의 장사 소개) → 장사 시작
  → [주문 들어옴] → 틀 고르기 → 반죽 붓기 → 소 넣기 → 뚜껑 닫고 굽기
  → 뒤집기 타이밍(Perfect/Good/탐/덜익음) → 완성·서빙 → 점수·콤보
  → (시간/주문 수 소진) → 오늘의 결과 카드 → 공유 · 다시 하기 · 내일 또
```

- 한 판은 **시간제(예: 90초)** 또는 **주문 수제(예: 손님 12팀)** 중 하나로 끝낸다(5.5에서 택1).
- 여러 틀을 동시에 굽는 멀티태스킹이 긴장을 만든다(5.3).

## 5. 게임 메커니즘

### 5.1 한 번의 붕어빵(핵심 루프) — 2026-11-08 플레이 피드백 반영

1. **주문**: 손님이 "팥 2개"처럼 주문한다. 주문 카드가 위에 쌓이고, 인내 막대(13초)가 줄어든다.
2. **소 고르고 반죽 붓기**: 소(팥·슈크림, 후반 고구마)를 고르고 빈 틀(4칸)을 누르면 붓는다.
   **한번 부은 반죽은 뺄 수 없다** — 다 굽거나 태우거나 둘 중 하나다.
3. **굽기·꺼내기**: 익힘 게이지가 찬다. 초록 구간 전에는 **꺼낼 수 없고**("아직 덜 익었어요"),
   초록 한가운데서 꺼내면 완벽, 가장자리면 좋음, 지나면 탐. 꺼낸 붕어빵은 **거치대**로 간다.
4. **거치대(3칸)**: 틀(4칸)보다 적어 쌓아 두기만 할 수는 없다. 꽉 차면 꺼낼 수 없어 틀 위에서
   계속 익다가 탄다. 거치대에 **8초마다 한 단계씩 식는다**(완벽 → 좋음 → 식음, 탄 것은 그대로).
   방금 꺼낸 것은 고른 게 없으면 자동으로 골라진다.
5. **서빙·버리기**: 거치대에서 붕어빵을 고른 뒤 **주문 카드를 누르면 서빙**, **🗑️를 누르면 버린다**.
   고른 붕어빵과 소가 같은 주문 카드가 강조된다.

### 5.2 판정과 점수

| 상황 | 점수 | 비고 |
| ---- | ---- | ---- |
| 완벽(Perfect) 서빙 | 100 × 콤보 | Perfect 3연속마다 배수 +1, 최대 ×3 |
| 좋음 서빙 | 70 | 콤보 끊김 |
| 식음 서빙 | 40 | 콤보 끊김 |
| 다른 소를 내밂 | −30 | 손님이 거절, 붕어빵은 거치대에 남음, 콤보 끊김 |
| **탄 것을 내밂** | **−50** | 손님이 거절, 붕어빵은 거치대에 남음 → 쓰레기통에 버려야 함 |
| 쓰레기통에 버림 | 0 | 칸만 비운다(결과에 버린 개수 집계) |
| 손님이 떠남 | 0 | 결과에 놓친 손님 수 집계 |

- 점수는 **결정론적 규칙 + 플레이어 입력 타이밍**으로 정해진다. 운 요소(주문 순서)는 시드로 고정한다.
- 점수는 0 아래로 내려가지 않는다. 판정은 꺼낼 때, 점수는 손님이 받을 때 매긴다.

### 5.3 난이도 곡선

- 처음엔 틀 4칸·소 2종(팥·슈크림)·느린 주문. 장사가 진행될수록 틀 6칸·소 3종·주문이 빨라지고
  겹친다. "오늘의 장사"는 시드로 정해진 **고정 흐름**이라 같은 날이면 모두 같은 난이도를 겪는다.
- 익힘 속도·초록 구간 폭을 조절해 난이도를 만든다(후반엔 구간이 좁아진다).

### 5.4 랜덤과 결정론

- 견생극장처럼 **시드 난수 생성기**(순수 TS)를 쓴다. 같은 시드면 **주문 순서·소 종류·타이밍 창**이
  똑같이 재현된다. 점수 차이는 오직 플레이어의 손에서만 난다. 랭킹전·고스트·버그 재현의 토대다.
- 일일 챌린지 시드는 **오늘 날짜(UTC)**에서 만든다. 로컬 자정이 아니라 UTC로 통일해 **전 세계가
  같은 날 같은 판**을 받는다(Wordle 방식). "연습 모드"는 무작위 시드로 돌린다.

### 5.5 한 판 종료 방식 (확정: 시간제)

- **시간제, 90초.** 90초 동안 최대한 많이·정확히 굽는다. 끝이 명확하고 점수 비교가 쉬워 랭킹에
  맞다. 시드로 주문 흐름이 고정되므로 같은 날이면 모두 같은 90초를 겪는다.
- (대안이던 "주문 수제"는 쓰지 않는다. 느린 사람도 끝까지 가는 장점은 있으나 끝 시점이 사람마다
  달라 점수 비교가 덜 깔끔하다.)

## 6. 랭킹 시스템 — 서버 없이 겨루기 (핵심)

**확정: 1단계는 완전 무서버로 출시한다.** 전역 순위표(온라인)는 처음 목표로 두지 않고, 무서버로
"같은 판·비교·공유"의 재미를 확인한 뒤 수요가 있으면 나중에 얹는다(6.2). 아래는 그 비교·근거다.

### 6.1 무서버 비동기 경쟁 (확정, 송이랜드 원칙 부합)

서버 없이도 "같은 판으로 경쟁"하는 느낌을 세 가지로 만든다.

1. **시드 기반 일일 챌린지**: 오늘 날짜(UTC)를 시드로 "오늘의 장사"를 생성한다. 인프라 0으로
   전 세계가 동일한 주문 흐름을 받는다. 결과 카드에 날짜·점수를 적어 공유하면 Wordle처럼
   비동기로 비교된다.
2. **로컬 최고기록 + 고스트**: 내 최고 기록의 입력(타이밍 로그)을 `localStorage`에 저장하고,
   다음 플레이 때 **고스트**(반투명 손놀림/진행 막대)로 같이 띄워 자기 자신과 경쟁한다.
3. **공유 카드**: "2026-11-07 오늘의 장사 · 1,840점 · 콤보 ×3 · Perfect 9개"를 PNG로 만들어
   저장·공유한다. 로또쇼·견생극장과 같은 Canvas 패턴.

장점: 서버·계정·개인정보 0, 비용 0, 치팅이 리더보드를 오염시킬 일 자체가 없음(로컬 기록은 본인
것뿐). 송이랜드 "서버 없음" 원칙에 완벽히 맞는다. 단점: **전역 순위표(1~100등)는 없다.**

### 6.2 나중 선택지 — 온라인 전역 순위표 (지금은 안 함)

전역 순위표가 나중에 꼭 필요해지면, 정적 Pages 앞단은 그대로 두고 **Cloudflare Worker + 저장소**를
API로 붙인다. 로그인은 두지 않고 닉네임만 받는다. 아래는 그때를 위한 메모다.

| 저장소 | 2026 무료 티어 | 글로벌 하이스코어 적합성 |
| ------ | -------------- | ------------------------ |
| Workers KV | 읽기 10만/일, **쓰기 1,000/일**, 결과적 일관성 | **부적합.** 점수 제출(쓰기) 1,000/일 병목 + "방금 올린 점수가 바로 안 보임". 설정·캐시용으로만. |
| **D1 (SQLite)** | 행 읽기 500만/일, **쓰기 10만/일**, 5GB, 강한 일관성 | **권장.** `ORDER BY score DESC LIMIT 100`으로 순위가 자연스럽고 쓰기 한도도 넉넉. |
| Durable Objects | 요청 10만/일 | 실시간·다수 리더보드엔 강하나 단일 전역 순위표엔 과함. |

치팅 방어(로그인 없는 공개 순위표의 최소 조합): **① Cloudflare Turnstile**(점수 제출 시 사람
확인, 서버에서 토큰 검증 뒤에만 신뢰) **② IP 레이트리밋**(분당 N회) **③ 서버측 "말도 안 되는
점수" 상한 검사**(인간이 낼 수 없는 점수/시간 조합 거부). 완전한 리플레이 재검증은 캐주얼 게임엔
과하다 — "치팅을 느리게" 만드는 선에서 타협한다. 선택적으로 제출 토큰을 서버 비밀키로 HMAC
서명해 재사용·위조를 막는다.

> KV는 리더보드 저장소로 쓰지 않는다(쓰기 1,000/일 + 결과적 일관성).
> 외부 관리형 DB(Supabase·Firebase 무료 티어)는 빠르지만 anon 키가 클라이언트에 노출돼 RLS/보안
> 규칙 없이는 점수 위조에 그대로 노출되고, 앱별 독립 배포·무서버 원칙과 외부 의존이 늘어난다.

### 6.3 추천 매트릭스

| 옵션 | 구현 노력 | 비용 | 치팅 저항 | 무서버 원칙 |
| ---- | --------- | ---- | --------- | ----------- |
| **무서버(일일챌린지+고스트+공유)** | 낮음 | 0 | 해당 없음(로컬만) | ★★★ 완벽 |
| Worker + D1 + Turnstile + 레이트리밋 + 상한검사 | 중 | 0(무료 티어) | 중 | ★★ Worker 추가 |
| Worker + D1 + 리플레이 재검증 | 높음 | 0~낮음 | 높음 | ★★ 과함 위험 |
| 외부 관리형 DB 공개 API | 낮음~중 | 0(쿼터 내) | 낮음(규칙 필수) | ★ 외부 의존 |

**결론(확정)**: 무서버로 출시해 "랭킹전"의 핵심 재미(같은 판·비교·공유)를 먼저 확인하고, 수요가
있으면 나중에 **Worker + D1 + Turnstile + 레이트리밋 + 점수 상한 검사**를 최소 조합으로 얹는다.

코랄 강조)을 쓴다.

| 화면 | 구성 |
| ---- | ---- |
| 시작 | 게임 소개, "오늘의 장사 시작", 오늘 내 최고 점수, 내 가게 영업, 상점(보유 포인트), (나중 선택지) 순위표 버튼 |
| 상점 | 업그레이드 4종(단계·다음 효과·값), 보유 포인트. 내 가게에만 적용된다는 안내 |
| 장사(플레이) | 붕어빵 틀판(4~6칸·익힘 게이지), 주문 줄, 남은 시간(90초), 소 선택, 점수·콤보 |
| 결과 | 오늘 점수·콤보·판정 집계, 날짜, 최고 기록 대비, 영수증(매출·재료비·순이익·포인트), `이미지로 저장`·`공유`·`다시 하기` |

- 모바일 세로 우선(한 손 터치). 데스크톱은 키보드(스페이스=뒤집기 등)도 받는다.

## 8. 비주얼·사운드와 "손맛"(게임 필)

만족스러운 타이밍/뒤집기 감각은 규칙이 아니라 **피드백 레이어**에서 나온다. 과하지 않게,
판정 등급(Perfect/Good/탐)에 따라 **강도를 차등**해서 쓴다.

- Perfect: 짧은 **히트스톱**(몇 프레임 정지) + 반짝임·김 파티클 + 숫자 팝(톡 튀어 커졌다 줄기)
  + "딱!" 성공음 + 1프레임 흰 플래시. Good은 그 절반 세기, 실패는 연기/흐물 표시만.
- 과잉 금지: 가독성을 해치지 않는다. `prefers-reduced-motion`이면 흔들림·플래시를 끈다.
- 사운드는 **라이선스 확인 전엔 넣지 않는다**(견생극장 11.1의 CC0 우선 규칙과 운영 규칙을 그대로
  따른다). 필요하면 Web Audio로 만든 짧은 효과음부터.

## 9. 저장과 공유

- `localStorage` 네임스페이스는 **`songiland:bbang:*`**(예: `songiland:bbang:best:v1`,
  `songiland:bbang:ghost:v1`). 로또쇼·견생극장처럼 저장이 막힌 환경(시크릿 모드)에서는
  메모리 대체 + "기록이 유지되지 않을 수 있어요" 안내를 띄운다.
- 일일 챌린지 최고 기록은 **날짜별**로 둔다(오늘 기록 깨기, 최근 30일). 연습 모드 최고점은 따로.
- **고스트(3단계 구현)**: 판을 바꾼 입력만 `{atMs, input}` 로그로 남긴다(`session.inputs`). 오늘
  최고 기록을 깨면 그 판의 로그를 `songiland:bbang:ghost:v1`에 둔다. 다음 판 시작 때 같은 장사에
  로그를 다시 돌려(순수 리듀서라 그대로 재현) **점수가 저장값과 같을 때만** 점수 흐름을 띄운다
  ("👻 오늘 최고 기록 N점 · +120 앞섬"). 규칙을 바꾸면 `RULES_VERSION`을 올려 옛 고스트를 버린다.
  같은 점수는 기록을 바꾸지 않는다.
- 결과 카드는 Canvas로 PNG(1080×1350, 인스타 4:5)를 만들어 저장/공유한다. 날짜·점수·콤보·
  판정 집계·판 개수·매출·놓친 손님·붕어빵 그림·점수대별 밈 한 줄(12장)만 담고 개인정보는 받지
  않는다. 파일 이름은 `붕어빵랭킹전-YYYY-MM-DD.png`(내 가게는 `붕어빵랭킹전-내가게.png`).
  결과 화면이 열리면 미리 그려 둬, 휴대폰 공유 시트를 버튼 직후에 열 수 있게 한다(견생극장과 같음).

## 10. 기술 구성

- 새 앱: `apps/bbang`. React + Vite + TypeScript, **새 라이브러리 없이** React만. 공통 패키지
  (`@songiland/ui`, `@songiland/catalog`, `@songiland/test-config`, `@songiland/eslint-config`)를 쓴다.
- **게임 엔진은 순수 TypeScript**로 분리한다(견생극장 패턴). 시드 난수로 "오늘의 장사"를 만들고,
  입력(틀 선택·뒤집기 타이밍)을 받아 점수를 결정론적으로 계산한다. 화면·시계·DOM에 기대지 않는다.
  - 진행 타이머는 `setInterval`이 아니라 **경과 시간 기반**으로 계산해 탭을 비워도 몰아 처리되지
    않게 한다(탭 숨기면 일시정지). 견생극장 `useRunClock` 패턴 참고.
- 카탈로그 등록: `packages/catalog/src/index.ts`의 `domains`에 `{ id:'bbang', kind:'game',
  title:'붕어빵 랭킹전', description:'…', emoji:'🐟' }`, `appHosts`에
  `{ subdomain:'bbang', devPort:5177, previewPort:4177 }`를 더한다. 기존 포트는 5173~5176 ·
  4173~4176이 쓰이므로 **5177 / 4177**을 쓴다(카탈로그 테스트가 중복·형식을 강제한다).
- 포털 카드는 카탈로그에서 자동 생성되므로 포털 코드는 손대지 않는다.
- 배포: 앱별 **Cloudflare Pages 프로젝트** 하나(정적). 빌드 `pnpm --filter bbang build`,
  출력 `apps/bbang/dist`, 커스텀 도메인 `bbang.arosys.kr`. README 배포 표에 한 줄 추가. Pages
  프로젝트 생성·DNS는 개발자.
- 테스트: 엔진 단위(시드 재현, 점수 규칙, 일일 시드가 UTC로 같은지), 컴포넌트(틀·판정 표시),
  e2e 1~2개(시작 → 몇 번 굽기 → 결과 카드 → 공유 PNG). 공유 카드 레이아웃 테스트는 견생극장
  `share/card.test.ts` 패턴을 따른다.
- (나중에 온라인 랭킹을 할 때만) 별도 Worker + D1. 비밀키·Turnstile 키는 Pages/Worker 환경변수로
  두고 저장소에 커밋하지 않는다.

## 11. 윤리·법적 점검

- **돈·포인트·상품이 없다**(점수뿐). 사행성과 거리가 멀다. 로또쇼 법적 검토의 "사운드·서버 미사용,
  재화 없음" 전제와 어긋나지 않는다. 사운드·온라인 랭킹을 넣는 시점에 해당 검토를 갱신한다.
- 그림·글·소리는 모두 자체 제작하거나 라이선스를 확인하고 기록한다(실존 브랜드·가게 이름 안 씀).
- 온라인 랭킹을 넣으면 닉네임만 받고(개인정보 최소), Turnstile·레이트리밋·부적절 닉네임 필터를 둔다.
  개인정보·쿠키 처리 고지가 필요한지 그 시점에 확인한다.
- 붕어빵 가격·물가 밈은 **가벼운 플레이버**로만 쓰고 특정 상호·실제 영업을 겨냥하지 않는다.

## 15. 가게 경제 — 매출 → 포인트 → 업그레이드 (확정·구현, 2026-11-10)

> 플레이 피드백에서 나온 제안. **랭킹 판은 표준 조건**, 업그레이드는 **'내 가게' 모드에서만** 적용
> 하기로 정했다(같은 날 같은 판이라는 랭킹전의 공정성을 지킨다). 3.5단계로 구현했다.
> 아래 숫자는 첫 값이고 5단계(밸런스)에서 플레이해 보며 맞춘다. 수치는 `engine/shop.ts`에 모여 있다.

### 15.1 두 모드

| 모드 | 장사 | 가게 | 점수·기록 | 포인트 |
| ---- | ---- | ---- | --------- | ------ |
| **오늘의 장사**(랭킹) | 날짜(UTC) 시드, 모두 같은 판 | **표준 가게**(틀 4·거치대 3·기본 반죽) | 날짜별 최고점·고스트·공유 카드 | 번다 |
| **내 가게**(지금의 연습 모드를 바꿈) | 무작위 시드 | **내가 키운 가게**(업그레이드 적용) | 내 가게 최고점 | 번다 |

### 15.2 매출과 재료비 (한 판)

- **매출**: 손님이 받아 준 붕어빵마다 판매가. 기본 **1,000원**("1,000원에 단 한 마리" 밈, 12장).
  팁: 완벽 +300원, 좋음 +100원, 식음 0원. 고구마는 1,200원.
- **재료비**: 반죽을 부을 때마다 원가(12장 보도 수치: 팥 약 220원, 슈크림 약 250원, 고구마 약 300원).
  **태우거나 버린 것도 재료비는 나간다** → 매출이 점수와 다른 "가게 운영" 감각을 준다.
- **순이익 = 매출 − 재료비**(0 미만이면 0). 결과 화면에 매출·재료비·순이익을 영수증처럼 보여 준다.
- 점수(랭킹)와 매출(경제)은 **따로 계산**한다. 점수 규칙은 그대로 두어 고스트·기록이 흔들리지 않는다.

### 15.3 포인트

- 순이익 **100원 = 1P**(내림). 두 모드 모두 번다. 어림잡아 한 판 순이익 1~3만 원 → **100~300P**.
- 포인트는 이 브라우저에만 저장(`songiland:bbang:wallet:v1`: 보유 P·누적 매출·업그레이드 단계).

### 15.4 상점 (영구 업그레이드, '내 가게'에만 적용)

| 업그레이드 | 효과 | 단계별 값 |
| ---------- | ---- | --------- |
| 거치대 넓히기 | 거치대 3 → 4 → 5칸 | 250P · 500P |
| 틀 늘리기 | 굽는 틀 4 → 5 → 6칸 | 300P · 600P |
| 비싼 반죽 | 초록 구간 폭 +10% → +20%, 판매가 +200원, 재료비 +100원 | 400P · 800P |
| 보온 거치대 | 식는 간격 8 → 11 → 14초 | 250P · 500P |

- 다 사는 데 3,600P ≈ 보통 실력 10판(5단계 측정으로 처음 값 2,250P에서 올림, 16.2). 단계는 순서대로만 산다. 환불·초기화는 첫 출시엔 두지 않는다.
- 엔진 쪽은 장사 시작 때 **가게 설정(틀 수·거치대 수·초록 폭 배수·식는 간격)**을 받는 형태로 바꾼다.
  오늘의 장사는 늘 표준 설정을 넣으므로 시드·고스트·점수 재현성은 그대로다.

### 15.5 윤리 점검

- 포인트는 **실제 돈으로 살 수 없고 바꿀 수도 없다**. 확률형 보상(뽑기)이 없다. 11장 전제와 맞는다.

## 16. 손맛과 밸런스 (5단계, 2026-11-11)

### 16.1 판정 피드백 (8장 구현)

| 순간 | 완벽 | 좋음 | 탐 |
| ---- | ---- | ---- | -- |
| 틀에서 꺼낼 때 | 히트스톱 90ms + 반짝이 8개 + "딱!" + 흰 플래시 | 히트스톱 40ms + 반짝이 4개 | 연기 3줄기 |
| 손님이 받을 때 | 점수 숫자 팝(200점 이상이면 크게) + "완벽! ×2" | 숫자 팝 | (거절) 빨간 음수 팝 |

- **히트스톱**은 장사 시계를 그만큼 멈춘다(`useShiftClock`이 돌려주는 `hitstop`). 입력 로그는
  게임 시간으로 남으므로 고스트·리플레이는 그대로 재현된다.
- 흰 플래시는 게임 시간 60ms 동안만 그리고 기본 투명도를 0으로 둬, 애니메이션이 멈춘 환경에서도
  화면을 덮지 않는다. 반짝이가 틀 밖으로 날아가도 가로 스크롤이 생기지 않게 `.play`를 자른다.
- `prefers-reduced-motion`이면 반짝이·연기·플래시를 끄고 "딱!"·숫자는 잠깐 보였다 사라지기만 한다.
- 손님이 기다리다 떠나면 "손님이 기다리다 갔어요" 알림과 함께 **콤보가 끊긴다**.

### 16.2 밸런스 측정과 조정

반응 간격·타이밍 오차가 다른 봇 세 종류로 30판씩 돌려 맞췄다(`src/game/balance.test.ts`가
기준선을 회귀 테스트로 지킨다).

| 봇(표준 가게) | 조정 전 점수 · 최고 콤보 · 포인트 | 조정 후 점수 · 최고 콤보 · 포인트 |
| ------------- | ------------------------------- | ------------------------------- |
| 초보(0.6초 · ±0.5초) | 2,709 · 6 · 200P (손님 13/31 놓침) | 2,254 · 5 · 196P (12/29) |
| 보통(0.4초 · ±0.25초) | 7,180 · 15 · 385P | 5,576 · 11 · 358P |
| 고수(0.25초 · ±0.12초) | 12,929 · 40 · 517P | 11,663 · 34 · 497P |

- **Perfect 폭**: 초록의 50% → **40%**. 보통 실력도 거의 콤보가 안 끊겨 ×3이 기본이 되던 문제.
- **막판 주문 간격**: 1.8초 → **2.2초**. 초보가 손님 40%를 놓치던 것을 조금 풀었다(초보의 한계는
  동작 수라 일부는 남는다 — 랭킹전이라 다 못 받는 게 정상).
- **손님이 떠나면 콤보 끊김**: 굽기만 잘하고 손님을 놓치는 플레이를 막는다.
- **상점 값**: 한 판 포인트가 예상(100~300P)보다 많아 약 1.6배로 올렸다(15.4).
- **밈 문구 기준**: 1,500 / 4,000 / 8,000점(초보·보통·고수 사이). 처음 값(500/1,500/3,000)은
  거의 모두가 최고 문구를 받았다.
- 규칙이 바뀌어 `RULES_VERSION`을 3으로 올렸다(옛 고스트는 버린다).
