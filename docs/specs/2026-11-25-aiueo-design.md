# 아이우에오 기획서 — 일본어 첫 글자 학습 앱

> 상태: **초안 · 검토 중** · 2026-11-25 (2026-11-26 단계 순서 변경, 2026-11-28 2단계 결정 반영) · 대상 앱 `apps/aiueo` (`aiueo.arosys.kr`)
>
> 일본어 기본 문자(히라가나부터)를 휴대폰에서 보고, 듣고, 쓰고, 말하며 익히는 학습 앱의
> 기획·분석 문서다. 14장의 열린 질문이 정해지면 상태를 "확정"으로 바꾼다.

## 1. 한 줄 소개

문자카드를 넘기듯 가나를 보고 듣고, 획순대로 쓰고, 따라 말하고, 퀴즈로 확인하는
**휴대폰 우선 가나 학습 앱**. 로그인 없이 열자마자 쓰고, 오프라인에서도 소리까지 나온다.

## 2. 확정된 결정 (2026-11-25 개발자 답변)

| 항목 | 결정 |
| ---- | ---- |
| 1차 문자 범위 | **히라가나만 먼저**(청음·탁음·반탁음·요음·촉음·장음 규칙). 가타카나는 2차 |
| 문자 따라 말하기 | **녹음 후 비교 듣기**(자가 평가) |

| 북마크 | 원하는 문자만 모아 모든 학습 방식의 범위로 쓸 수 있어야 함 |
| 이름 | **「아이우에오」**, 앱 id·주소 `aiueo` / `aiueo.arosys.kr`, 카탈로그 종류 `study`(신설) |
| 카드 설명 | "보고 듣고 쓰는 일본어 첫 글자" — 이름은 고정, 설명은 범위가 넓어질 때 바꾼다 |

### 2.1 이름을 고른 이유

- 진도·북마크는 주소(origin)별로 기기에 저장되므로 주소를 바꾸면 기록과 홈 화면 설치가 끊긴다.
  그래서 이름은 가장 멀리 갈 범위(가타카나 → 기초 단어 → 한자 입문)에 맞췄다.
- 일본어를 전혀 모르는 한국 사용자도 "아이우에오"는 안다(일본어판 "가나다"). 듣고 바로 주소를 칠 수 있다.
- 앱을 열고 처음 배우는 다섯 글자가 あいうえお라서 이름과 첫 경험이 같다.
- `kana`는 단어·한자로 넓히면 이름이 틀어지고, `nihongo`는 정확하지만 흔하다.
- 일반 명사라 같은 이름의 앱·사이트가 있을 수 있다. 서브도메인 운영에는 문제없고, 앱스토어 출시·상표
  등록 때 다시 확인한다.

## 3. 사용자와 성공 기준

- 대상: 일본어를 처음 시작하는 한국어 사용자(우선 개발자 본인). 이동 중 한 손, 1~5분 단위 사용.
- 성공 기준
  - 휴대폰에서 앱을 열고 **3초 안에 첫 카드**를 보고 소리를 들을 수 있다.
  - 비행기 모드에서도 카드·소리·쓰기·퀴즈가 동작한다(음성 인식 채점만 예외).
  - 히라가나 청음 46자를 "문자만 보고 발음 맞히기" 90% 이상으로 끌어올릴 수 있는 학습 흐름이 있다.
  - 북마크한 문자만으로 모든 학습 방식을 돌릴 수 있다.
  - 진도·북마크가 앱을 닫아도 남는다.

## 4. 학습 내용 (1차: 히라가나)

| 단원 | 내용 | 문자 수 | 비고 |
| ---- | ---- | ------- | ---- |
| 청음 | あ행~わ행, ん | 46 | 행 단위(5자)로 묶어 학습 |
| 탁음·반탁음 | が·ざ·だ·ば행, ぱ행 | 25 | ぢ·づ는 じ·ず와 같은 소리임을 안내 |
| 요음 | きゃ·しゃ·ちゃ … ぴょ | 33 | 쓰기는 작은 ゃゅょ 크기·위치 중심 |
| 촉음 | っ | 1 | **단독 발음이 없다** → 단어 쌍으로 학습(きて/きって) |
| 장음 | ああ·いい·うう·えい·おう | 규칙 5종 | **문자가 아니라 규칙** → 단어 쌍으로 학습(おばさん/おばあさん) |
| 읽기 예외 | 조사 は(wa)·へ(e)·を(o) | 3 | 카드 뒷면 주석 + 예문 한 줄 |

- 촉음·장음·ん은 낱자 카드로는 익혀지지 않는다. "소리 길이 구별" 듣기 문제(둘 중 어느 쪽?)를 따로 둔다.
- 각 문자에 예시 단어 2~3개(쉬운 기초 단어, 뜻·읽기 포함)를 붙인다. 총 150~200개. 직접 작성한다.
- 발음 표기는 **로마자(헵번식) 기본 + 한글 근사 표기 보조**. 한글 표기는 つ·ず·う 등에서 부정확하므로
  "근사"임을 표시하고 설정에서 끌 수 있게 한다. 소리가 기준이고 표기는 보조다.
- 2차: 가타카나 전 범위(장음 부호 ー, 외래어 확장 표기 ティ·ファ 등 포함), 히라가나↔가타카나 짝 맞추기.

## 5. 발음 음원 — "전문 교육 앱이라면"에 대한 답

**권장: 고품질 음성을 미리 파일로 만들어 앱에 함께 배포한다. 실행 중 브라우저 내장 TTS에는 기대지 않는다.**

전문 학습 서비스가 쓰는 방식은 둘이다.

1. **원어민 성우 녹음** — 가장 좋지만 비용·섭외가 필요하다. 지금 단계에서는 과하다.
2. **신경망 TTS로 사전 생성 + 사람이 검수** — 대형 학습 앱 다수가 쓰는 방식. 문자·단어 수백 개를
   한 번 생성해 정적 파일로 둔다. 이 앱에 맞는 방식이다.

브라우저 내장 TTS(Web Speech API)를 실행 중에 쓰지 않는 이유:

- 기기·브라우저마다 목소리가 다르고, 일본어 음성이 없는 기기에서는 소리가 안 난다.
- 한 글자 입력을 문맥 없이 읽어 틀리는 경우가 있다(は·へ, っ, 작은 가나 등).
- 일부 음성은 온라인이어야 동작한다 → "언제 어디서든" 목표와 충돌.
- 교육 앱에서 **틀린 발음을 들려주는 것은 소리가 없는 것보다 나쁘다.**

### 5.1 생성 방식

- 저장소에 **일회성 생성 스크립트**와 대본 파일(문자·단어 → 읽기)을 둔다. 개발자가 로컬에서 실행하고,
  결과 음원을 `apps/aiueo/public/audio/`에 커밋한다. 앱 빌드·실행은 생성 엔진에 의존하지 않는다.
- 엔진 후보(14장 열린 질문 1)

| 후보 | 장점 | 주의 |
| ---- | ---- | ---- |
| 로컬 TTS 엔진(예: VOICEVOX) | 무료, 로컬 실행, 가나 단위로 읽기·억양 지정 가능 | 음성(캐릭터)별 이용 약관·크레딧 표기 확인 필요 |
| 클라우드 신경망 TTS(Google·Azure 등) | 자연스러운 표준 발음, SSML로 읽기 지정 | 계정·과금(소량은 무료 구간 가능), 생성물 재배포 약관 확인 필요 |

- 어느 쪽이든 **라이선스·약관은 채택 전에 원문으로 확인**하고 `THIRD_PARTY_NOTICES.md`에 음원 고지를 추가한다.
- 분량 추정: 문자 104개 + 단어 150~200개 + 길이 구별 쌍 ≈ 300개 내외. 모노 저비트레이트로 개당
  10KB 안팎이면 전체 3~5MB.
- **검수**: 생성 후 전 파일을 한 번씩 들어 본다(특히 ん, を, づ, 요음, 장음 쌍). 이상한 파일은 읽기 지정을
  바꿔 재생성한다. 검수 여부를 대본 파일에 표시한다.
- 재생은 `HTMLAudioElement`/Web Audio. iOS는 첫 재생에 사용자 터치가 필요하므로 자동 재생은
  "카드를 넘기는 터치" 직후에 건다. 느리게 듣기(0.75배)는 `playbackRate`로 처리한다.
- 음원 계층은 `play(id)` 하나로 감싸 나중에 성우 녹음으로 교체할 수 있게 한다.

### 5.2 음원이 준비되기 전 (임시 브라우저 음성)

- 음원 파일 목록(`src/audio/manifest.ts`)에 있는 문자만 파일로 재생하고, 없는 문자는 브라우저 내장
  음성(Web Speech API, `ja-JP`)으로 읽는다. 8단계에서 생성 스크립트가 목록을 채우면 문자별로 자동
  전환된다. 없는 파일을 요청했다가 실패하는 방식은 쓰지 않는다(iOS는 터치 직후가 아니면 음성을 막는다).
- 일본어 음성이 없는 기기에서는 "이 기기에서는 아직 소리를 낼 수 없어요"를 보여 준다.
- 임시 음성은 5장 첫머리의 이유로 정식 출시(9단계) 전에 모두 파일로 바꾼다.
- 소리는 항상 터치·클릭 처리 안에서 바로 재생한다(화면 전환 뒤 효과로 재생하지 않는다).

## 6. 학습 방식

모든 방식은 같은 **범위 선택기**를 쓴다: 행별(あ행…), 단원별, **북마크**, 복습할 문자, 약한 문자, 전체.

- 복습할 문자: 읽기 숙련도의 복습일이 오늘이거나 지난 문자(풀어 본 적 없는 문자는 넣지 않는다).
- 약한 문자: 최근 5번 답 중 틀린 비율이 30% 이상인 문자. 오래전 오답은 창 밖으로 밀려나면 빠진다.
- 범위 id는 주소에 들어간다: `seion`, `row-ka`…, `mine`, `review`, `weak`.

### 6.1 문자카드

- 앞면: 큰 문자 하나. 뒷면: 로마자·한글 근사, 예시 단어(뜻 포함), 획순 미리보기.
- 탭 = 뒤집기, 좌우 스와이프 = 이전/다음, 🔊 = 다시 듣기, ⭐ = 북마크.
- 넘길 때 자동 재생(설정에서 끔), 순서 섞기, 자동 넘김(핸즈프리 듣기 모드)은 2차.

### 6.2 획순 쓰기

- 3단계: ① 획순 애니메이션 보기 → ② 흐린 안내선 위에 따라 쓰기 → ③ 안내선 없이 쓰기.
- 획 판정: 획마다 시작점·끝점 위치, 진행 방향, 경로와의 평균 거리로 느슨하게 판정한다. 틀리면 그 획만
  다시, 두 번 틀리면 힌트 애니메이션. 글씨 모양의 정밀 채점은 하지 않는다(순서·방향이 목표).
- 획 데이터: **KanjiVG**(가나 포함 획순 SVG, CC BY-SA 3.0) 사용을 권장. 필요한 히라가나만 추려
  JSON으로 변환해 넣고 출처·라이선스를 고지한다. 동일조건변경허락 범위는 채택 전 확인(열린 질문 2).
- 구현: SVG + Pointer Events. 캔버스 영역은 `touch-action: none`으로 스크롤과 충돌을 막는다. 외부
  라이브러리 없이 구현 가능하다.

### 6.3 듣고 따라 말하기

- **문자**: 원음 듣기 → 녹음(`MediaRecorder`) → 원음·내 소리 번갈아 듣기 → 스스로 "비슷해요/다시" 선택.
  녹음은 기기 메모리에만 두고 저장·전송하지 않는다.
- **단어**: 음성 인식(`SpeechRecognition`, `lang: ja-JP`)으로 자동 채점.
  - 인식 결과는 한자·가타카나로 돌아올 수 있다(ねこ → 猫). 단어마다 **허용 표기 목록**
    (`ねこ`, `猫`, `ネコ`)을 두고 대조한다.
  - 지원이 불안정한 브라우저(iOS Safari, Firefox 등)·오프라인에서는 자동으로 녹음 비교 방식으로 바꾼다.
  - 브라우저 음성 인식은 소리를 외부 서버로 보낼 수 있다. 첫 사용 때 한 번 알린다.
  - 인식 실패를 "발음이 틀렸다"로 단정하지 않는다. 문구는 "못 알아들었어요, 한 번 더"로 한다.
- 마이크 권한을 거부해도 나머지 학습은 그대로 동작한다.

### 6.4 문자 → 발음 퀴즈

- 문자를 보고 발음 고르기(4지선다). 보기는 로마자 또는 **소리 버튼**(표기 없이 귀로 고르기) 중 설정.
- 역방향: 소리를 듣고 문자 고르기.
- 오답 보기는 헷갈리는 짝에서 우선 뽑는다: は/ほ, ね/れ/わ, め/ぬ, さ/き/ち, る/ろ, い/り 등.

2026-11-28 2단계 결정(개발자 답변):

- **한 판**: 범위 한 바퀴, 최대 10문제. 범위가 10자를 넘으면(청음 전체 46자) 복습일이 된 문자 →
  아직 풀어 보지 않은 문자 → 나머지(낮은 상자부터) 순으로 10자를 골라 섞는다. 끝나면 결과 화면.
- **보기 표기**: 설정 화면 대신 학습 탭(퀴즈 시작 화면)의 옵션으로 고른다. 마지막 선택을 저장한다.
- **소리 보기**: 보기를 누르면 그 소리가 나고 선택만 된다. "이걸로"를 눌러야 답이 된다. 답을 낸 뒤에야
  로마자를 보여 준다.
- **iOS 제약**: 소리는 늘 탭 처리 안에서 낸다. 역방향은 첫 문제도 "▶ 듣기"를 눌러야 시작하고, 듣기
  전에는 보기를 누를 수 없다. 다음 문제 소리는 "다음 문제" 버튼 처리 안에서 바로 낸다. 문자를 보고
  답을 낸 뒤에는 그 클릭 안에서 정답 소리를 들려준다.
- **일본어 음성이 없는 기기**: 학습 탭에서 "듣고 고르기"와 "소리 보기"를 끄고 이유를 보여 준다. 미리
  확인을 통과했는데 재생이 실패하면(목소리 목록을 늦게 받는 기기) 소리 보기는 로마자 보기로 바꾸고,
  듣고 고르기는 "보고 고르기로 바꾸기" 안내를 띄운다.
- 소리가 같은 문자(お와 を)는 한 문제의 보기에 하나만 둔다(정답이 둘이 되거나 같은 로마자가 두 번 보이지
  않게).
- 문제 목록은 시작할 때 고정한다(카드 덱과 같음). 섞기 시드는 주소(`/quiz/<범위>?shuffle=`)에 넣고,
  푼 진도는 주소에 남기지 않는다(새로 고치면 같은 시드로 처음부터).
- 정답·오답은 화면 읽기 프로그램에 `aria-live`로 알린다. 보기·버튼은 44px 이상.
- 결과 화면은 점수와 틀린 문자를 보여 주고, 문자마다 ☆ 담기와 "틀린 문자 모두 담기"를 둔다.

### 6.5 단어 속 문자 고르기

- 단어의 한 글자를 빈칸으로 보여 주고(뜻 + 소리 제공) 알맞은 문자를 고른다. 예: `ね□`(고양이) → こ.
- 변형: 단어 전체를 보고 "이 단어에 들어 있는 문자"를 고르기, 소리만 듣고 빈칸 채우기.
- 촉음·장음 단원에서는 이 방식이 주 학습이다(きて vs きって 중 들리는 쪽 고르기).

### 6.6 오늘의 학습 (묶음 세션)

- 새 문자 5자(한 행)를 카드 → 쓰기 → 퀴즈 순으로 묶은 5분 세션 + 복습 차례가 된 문자.
- 개별 방식을 자유롭게 고르는 "자유 학습"과 병행한다.

## 7. 북마크와 복습

- ⭐ 북마크: 카드·퀴즈 결과·문자표 어디서든 켜고 끈다. 1차는 목록 하나("내 문자"). 여러 목록은 2차.
- 문자표(오십음도) 화면에서 길게 눌러 여러 개를 한 번에 북마크.
- 숙련도: 문자마다 5단계 상자(라이트너 방식). 맞히면 한 칸 위, 틀리면 1단계로. 상자별 복습 간격
  당일/1일/3일/7일/14일. 읽기·쓰기 숙련도는 따로 기록한다.
  - 처음 답하는 문자는 1단계에 있던 것으로 본다: 맞히면 2단계(내일 복습), 틀리면 1단계(오늘 복습).
  - 날짜는 기기 시간대의 달력 날짜로 센다. 계산 함수는 지금 시각(`now`)을 받아 테스트에서 고정한다.
  - 2단계는 읽기만 채운다(두 퀴즈 방향 모두 읽기). 쓰기는 같은 구조(`mastery.writing`)에 3단계가 채운다.
- "약한 문자"는 최근 오답률로 자동 구성되어 범위 선택기에 나온다(6장 첫머리).
- 문자표에 숙련도를 색으로 표시해 진도를 한눈에 보게 한다. 색만으로 구별하지 않도록 칸 아래 막대 길이로도
  단계를 보이고, 화면 읽기 프로그램에는 "숙련도 n단계"로 읽어 준다. 풀어 본 문자가 있으면 표 아래에 범례를 둔다.

## 8. 화면 구성 (휴대폰 우선)

| 화면 | 내용 |
| ---- | ---- |
| 홈 | 오늘의 학습 시작, 복습할 문자 수, 연속 학습일, 학습 방식 바로가기 |
| 문자표 | 오십음도 격자(단원 탭), 숙련도 색, 북마크 표시, 탭하면 문자 상세 |
| 문자 상세 | 큰 문자, 소리, 획순, 예시 단어, 북마크 |
| 학습 | 범위 선택 → 방식 선택 → 진행 → 결과(틀린 문자 북마크 제안) |
| 설정 | 자동 재생, 표기(로마자/한글 근사), 재생 속도, 데이터 내보내기·가져오기·초기화 |

- 하단 탭 3개(홈·문자표·내 문자) + 설정. 주요 버튼은 엄지 영역, 터치 대상 44px 이상.
  - 2026-11-28 현재(홈·설정 전): 하단 탭은 **문자표 `/` · 학습 `/study` · 내 문자 `/mine`**. 1단계의 카드 탭을
    "학습"으로 바꿨다. 학습 탭은 한 화면에서 위에 방식(카드 / 보고 고르기 / 듣고 고르기)과 보기 표기를
    고르고, 아래 범위를 누르면 바로 시작한다. 3단계 쓰기도 이 방식 목록에 붙인다. 예전 주소 `/cards`는
    학습 탭으로 연다. 내 문자 탭에는 "퀴즈 풀기"와 "카드로 보기"를 둔다.
- 세로 고정 기준, 큰 글꼴(문자는 화면 폭의 절반 이상). 일본어 글꼴은 교과서체 계열을 권장
  (さ·き·り는 인쇄체와 손글씨 모양이 달라 초학자가 혼동한다). 글꼴 선택은 열린 질문 3.
- 화면 주소·뒤로가기는 기존 앱(붕어빵)과 같은 방식을 따른다.

## 9. 저장

- 로그인·서버 없음. 북마크, 숙련도, 설정, 연속 학습일을 `localStorage`에 버전 붙은 JSON 하나로 저장한다.
  - 저장 칸 이름은 `songiland:aiueo:v1` 그대로 두고, 안의 `version`으로 형식을 가린다.
  - version 1(1단계): `{ version, bookmarks }`.
  - version 2(2단계): `{ version, bookmarks, mastery: { reading, writing }, settings: { studyMode, quizChoices } }`.
    숙련도 기록은 문자 id마다 `{ box, due: "YYYY-MM-DD", recent: [1, 0, …] }`(최근 답 10개).
  - 예전 형식은 읽을 때 `migrate`로 올리고(북마크는 그대로, 숙련도는 빈 기록), 다음에 저장할 때 새 형식으로
    덮어쓴다. 모르는 새 버전이나 깨진 값은 빈 기록으로 시작한다.
- 기기 변경용 **내보내기/가져오기**(JSON 파일 또는 복사 문자열)를 설정에 둔다.
- iOS는 장기간 미사용 사이트의 저장소를 지울 수 있다 → 홈 화면 추가(PWA 설치)를 안내한다.
- 기기 간 자동 동기화는 범위 밖(필요해지면 붕어빵 온라인 순위표와 같은 백엔드 검토).

## 10. 오프라인과 설치 (PWA)

- 웹 앱 매니페스트 + 서비스 워커로 홈 화면 설치와 오프라인 실행을 지원한다.
- 앱 셸과 문자·획 데이터는 설치 시 캐시, 음원은 첫 실행 뒤 백그라운드로 전부 받아 둔다(3~5MB).
  받는 중에도 필요한 소리는 즉시 네트워크로 재생한다.
- 구현 선택: 직접 쓴 작은 서비스 워커(의존성 없음) 또는 `vite-plugin-pwa`(설치 필요, 개발자가 실행).
  1차는 **직접 작성**을 권장한다 — 캐시 대상이 단순하고 다른 앱과 의존성을 맞추기 쉽다.

## 11. 기술 구성

- `apps/aiueo`: 기존 앱과 같은 React 19 + Vite + TypeScript, Vitest, Playwright, 공용 ESLint·테스트 설정.
- 카탈로그(`packages/catalog`): `domains`에 항목 추가, `appHosts`에 `aiueo`(devPort 5178, previewPort 4178).
  종류 `study`(포털 "학습" 묶음)를 새로 만든다.
- 폴더(안)

```text
apps/aiueo/src/
  data/        문자·단어·획 데이터(JSON/TS), 헷갈리는 짝
  audio/       play(id), 선로딩, 속도
  progress/    숙련도·북마크·설정 저장소(순수 로직 + localStorage 어댑터)
  features/
    cards/  writing/  speaking/  quiz/  word-quiz/  chart/  session/
  app/         화면 전환, 탭, 범위 선택기
apps/aiueo/public/audio/  생성한 음원
scripts/aiueo-audio/      음원 생성 스크립트·대본(앱 빌드와 분리)
```

- 순수 로직(숙련도 계산, 문제 출제, 획 판정, 인식 결과 대조)은 화면과 분리해 단위 테스트한다.
- 브라우저 API 지원 정리

| 기능 | API | 미지원 시 |
| ---- | --- | --------- |
| 소리 재생 | HTMLAudio / Web Audio | (전 기기 지원) |
| 쓰기 | SVG + Pointer Events | (전 기기 지원) |
| 녹음 | MediaRecorder + getUserMedia (HTTPS 필요) | 따라 말하기를 "듣고 소리 내어 보기"로만 진행 |
| 음성 인식 | SpeechRecognition (접두사 포함) | 녹음 비교로 대체 |
| 오프라인 | Service Worker | 온라인 전용으로 동작 |
