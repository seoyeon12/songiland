# 송이의 행운 로또쇼 기획서

> 상태: 구현 전 승인 기획 · 2026-08-26
>
> 이 문서는 송이랜드의 첫 미니게임을 정의한다. 실제 복권 발행·판매·당첨 확인 기능은 포함하지 않는다.

## 1. 목표

비숑 수컷 **송이**가 진행하는 3D 게임쇼 안에서 이용자가 한국 로또6/45 형식의 번호를 재미로 뽑는 웹 미니게임을 만든다. 첫 게임이지만 이후 송이랜드의 여러 미니게임이 공통 허브, 입력 처리, 접근성 설정을 재사용할 수 있어야 한다.

성공 기준은 다음과 같다.

- 데스크톱에서 마우스 클릭 또는 스페이스바로 6개 본번호와 1개 보너스 번호를 한 개씩 공개할 수 있다.
- 모바일 웹에서는 `발바닥 모드`를 켠 뒤 화면의 빈 영역을 터치해 같은 흐름을 진행할 수 있다.
- 결과는 같은 브라우저에만 저장되고, 최신 20건만 최대 24시간 보인다.
- 복권 구매, 결제, 상금, 회원 계정, 사운드, 실제 당첨 확인은 없다.

## 2. 규칙과 서비스 경계

동행복권 로또6/45의 숫자 범위와 추첨 형식을 참고해, 1~45 중 중복 없는 6개 본번호와 별도 보너스 번호 1개를 만든다. 공식 로또6/45에서 구매자가 고르는 번호는 6개이며, 보너스 번호는 실제 추첨의 당첨 등위 판단에 쓰인다. [동행복권 로또6/45 안내](https://m.dhlottery.co.kr/lt645/intro)

- 이 서비스는 **복권을 발행하거나 판매하지 않는다.**
- 화면의 6개 본번호만 `추천 본번호`로 표기한다.
- 보너스 번호는 게임쇼 연출과 로또 추첨 구조 소개를 위한 번호다. `실제 구매 번호는 본번호 6개뿐`이라는 설명을 결과 카드에 항상 표시한다.
- 결과가 실제 당첨 가능성, 당첨 확률 향상, 판매 결과를 보장한다고 주장하지 않는다.

## 3. 이용 흐름

### 3.1 시작

1. 이용자는 송이랜드 허브에서 `송이의 행운 로또쇼`를 연다.
2. 화면에는 3D 유리 추첨기, 비어 있는 6개 본번호 슬롯, 보너스 슬롯, 큰 `송이의 행운 발도장` 시작 버튼을 보여 준다.
3. 시작을 누르면 번호 7개를 먼저 확정하고, 추첨기는 공을 섞는 연출로 전환한다.

### 3.2 공 공개

| 환경 | 입력 | 동작 |
| --- | --- | --- |
| 데스크톱 | 발도장 버튼 또는 3D 추첨기 인터랙션 영역 클릭 | 시작 또는 다음 공 1개 공개 |
| 데스크톱 | 스페이스바 | 다음 공 1개 공개. 버튼·기록 패널 등 다른 조작 요소에 포커스가 있을 때는 작동하지 않음 |
| 모바일 | `발바닥 모드 ON` 후 화면의 빈 영역 터치 | 다음 공 1개 공개 |

- 1~6번째 공은 본번호 슬롯을 순서대로 채운다.
- 7번째 공은 조명 변화와 카메라 줌을 거쳐 다른 색의 보너스 공으로 공개한다.
- 한 번의 입력이 여러 공을 넘기지 않도록 각 공개 뒤 약 1초의 입력 잠금 시간을 둔다.
- 결과 확정 뒤 본번호는 읽기 쉬운 오름차순으로 정렬해 표시하되, 방금 공개된 순서는 짧게 다시 볼 수 있게 한다.

### 3.3 종료·기록

1. 결과 카드에 본번호 6개, 보너스 번호 1개, 추첨 시각, 재시작 버튼을 표시한다.
2. 하단의 `송이의 최근 행운 기록` 패널에서 24시간 이내의 결과를 볼 수 있다.
3. 새 결과를 저장하거나 기록 패널을 열 때 만료된 기록을 지우고, 최신 20건만 남긴다.
4. 다음 문구를 결과·기록 근처에 표시한다.

> 송이랜드의 오락용 번호 추천입니다. 실제 복권 발행·판매·당첨 확인 서비스가 아니며, 당첨을 보장하지 않습니다. 복권은 건전하게 즐겨주세요.

## 4. 비주얼과 연출

- 방향: 보송한 비숑 송이가 사회를 보는 **장난감 같은 네온 게임쇼**. 투명 유리 구체 안에서 색색의 공이 반짝이고, 발바닥 도장과 가벼운 파티클이 반응한다.
- 중심: 화면의 주인공은 3D 추첨기다. 번호·기록·안내는 고대비 웹 UI로 분리해 읽기 쉽게 유지한다.
- 사운드: 첫 버전에서 BGM·효과음을 제공하지 않는다.
- 송이 모델: 실제 비숑 송이의 3D 모델이나 초상형 자산은 아직 만들지 않는다. 구현 단계에서 주인장의 사진을 받은 뒤에만 모델링 또는 이미지 작업을 요청한다. 그 전에는 발바닥·실루엣 같은 임시 도형만 쓴다.
- 접근성: `모션 줄이기`를 켜면 강한 카메라 이동·파티클 대신 빠른 번호 전환을 사용한다. 사운드 설정은 사운드 자체가 없으므로 제공하지 않는다.
- 성능: 작은 모바일 화면 또는 저사양 기기에서는 그림자, 파티클, 장면 속 비선택 공의 수를 줄인다. WebGL을 쓸 수 없으면 같은 번호 흐름의 2D 결과 화면으로 전환한다.

## 5. 정보 구조와 확장 원칙

| 경로/영역 | 책임 |
| --- | --- |
| `/` | 송이랜드 게임 허브. 현재 게임과 이후 미니게임의 진입점 |
| `/games/lotto` | 송이의 행운 로또쇼. 로또 규칙·3D 장면·기록을 소유 |
| 공통 앱 셸 | 송이랜드 브랜딩, 게임 선택, 모션 설정, 공통 안내 |
| 로또 게임 모듈 | 번호 생성, 추첨 상태, 3D 연출, 로컬 기록을 독립 관리 |

다른 게임은 공통 앱 셸과 입력·모션 설정만 재사용한다. 로또의 번호 규칙, 기록 키, 추첨 상태는 다른 게임에서 가져다 쓰지 않는다.

## 6. 기술 설계

### 6.1 기반

- `Vite + React + TypeScript`로 앱과 게임 허브를 구성한다.
- Three.js는 React Three Fiber를 통해 사용한다. 3D 추첨기·공·카메라·조명만 3D로 만들고, 텍스트·기록·고지·버튼은 접근성 있는 일반 웹 UI로 만든다.
- 첫 버전은 서버, 로그인, 분석 도구, 외부 API를 사용하지 않는다.

### 6.2 책임 분리

| 단위 | 책임 | 의존/출력 |
| --- | --- | --- |
| `numberGenerator` | 암호학적 난수 기반으로 1~45 중 중복 없는 7개 선택 | 본번호 6개와 보너스 1개 |
| `drawStateMachine` | 대기, 혼합, 다음 공 대기, 공개, 완료 상태와 입력 잠금 관리 | 현재 공개할 공의 인덱스 |
| `lotteryScene` | 공의 움직임, 카메라, 조명, 파티클을 렌더링 | 이미 확정된 번호를 시각적으로 공개 |
| `historyRepository` | 브라우저 기록 읽기·만료 삭제·최신 20건 유지 | 유효한 기록 목록 |
| `gameShell` | 키보드·클릭·모바일 발바닥 입력을 게임 상태 전환으로 연결 | 공통 설정과 접근성 |

번호는 시작 시 `crypto.getRandomValues()`를 이용한 셔플로 먼저 확정한다. 물리 엔진이나 프레임 속도는 번호를 정하지 않고, 결과를 보여 주는 연출만 담당한다. 따라서 클릭·키보드·모바일 터치 어느 입력을 써도 한 번 시작한 추첨의 결과는 바뀌지 않는다.

### 6.3 기록 데이터

브라우저 `localStorage` 키는 버전을 포함한 `songiland:lotto:draws:v1`을 사용한다. 각 항목은 다음만 가진다.

```ts
type LottoDrawRecord = {
  id: string;
  drawnAt: string; // ISO-8601 UTC
  mainNumbers: [number, number, number, number, number, number];
  bonusNumber: number;
};
```

- `drawnAt` 기준 24시간이 지난 항목은 삭제한다.
- 유효한 항목이 20건을 넘으면 오래된 것부터 삭제한다.
- 이 데이터는 서버로 전송하지 않는다. 브라우저·기기 변경, 브라우저 데이터 삭제, 시크릿 모드에서는 유지되지 않을 수 있음을 안내한다.
- `localStorage`에 접근할 수 없으면 현재 탭의 메모리에만 기록하고, 기록이 유지되지 않을 수 있다는 상태 메시지를 표시한다.

## 7. 예외 처리와 검증

- 난수·기록 데이터가 손상되면 해당 기록을 폐기하고 새 추첨을 막지 않는다.
- 공개 애니메이션 중에는 시작·다음 번호 입력을 무시한다.
- 브라우저가 스페이스바를 페이지 스크롤에 쓰지 않도록, 게임 인터랙션 영역이 활성화된 경우에만 기본 동작을 막는다.
- 자동 검증 범위: 숫자 범위(1~45), 본번호 6개 및 보너스 번호의 중복 없음, 본번호 정렬, 24시간 만료, 20건 상한, 클릭·스페이스바·발바닥 터치의 동일한 상태 전환, 저장소 실패 대체 경로.
- 수동 검증 범위: 데스크톱 마우스/키보드, 모바일 터치, 모션 줄이기, 작은 화면, WebGL 미지원 안내의 동작.
